## Strict recovery

`PublishRetainedSummary.failed` uses the existing unchanged-source disposition.
It checks original publication links/route, recovery membership and file bytes,
and original stopped settings before transferring the canonical handoff through
`cutover_child.restore_stopped_batch`.

The child runs under the interpreter and environment captured from the original
3931 owner. The same integer wire descriptor crosses `pass_fds`. Original3931
strict-decodes the handoff and its own `StoppedOwnerBatch.accept(int)` validates
the resource and constructs its own `StoreLock`. No foreign phase object,
compatibility decoder, copied owner module or raw handoff mapping is needed.

Every source interpreter and retired owner witness must match before launch.
Partial retirement cannot enter complete-batch recovery. Changed bytes, route,
generation or uncertain launch retain the original failure and explicit stopped
disposition; they do not trigger automatic rollback, re-signal or retry.
