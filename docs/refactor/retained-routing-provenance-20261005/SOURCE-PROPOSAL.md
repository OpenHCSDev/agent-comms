## Proposed existing-owner repair

### Original recorded namespace acquisition

Extend the existing outside-src `OwnerReadProjection` / `read_original_owner`
acquisition family with recorded namespace acquisition. Original installed
`Registration.store.reading()` must decode and validate the original full
document. Recorded acquisition must not call `OwnerRestartSelection` or require
a live process merely to project evidence. Keep those checks on the existing
live-owner acquisition member.

The target declaration owns the requested provenance shape. Derive its field
contract from `ThreadProvenance` / `RegistryProvenance` and existing
`FieldCodec.record_schema`; do not copy a field roster into the original helper.
The original read member projects values from its already validated typed
declarations, preserves aliases, and emits only the requested recorded namespace
with original root/revision/incarnation evidence. The target strictly decodes
that namespace once with `FieldCodec`. Never import target application types
into the old producer, overlay source packages, infer versions from absent
fields, or target-decode a full old `Thread`.

`HistoryArchive.attach` consumes that acquired namespace before destination
publication. Reuse `HistorySource` for source/root/revision validation and final
archive ownership; do not create a second durable provenance catalog. Require
the acquisition to match the exact copied original registry/bus revisions and
original root identity. Preserve the existing before/after snapshot checks,
aliases, incarnation values, archive access policy and source byte preservation.
The original registry and guard remain intact. Same-declaration attachment
continues to use its original typed read and `RegistryProvenance.capture`.

The acquisition transport must be implemented in this existing owner family;
no production legacy reader, generic conversion service, retired-field
projection, or registry rewrite is proposed. Final method signatures belong to
this closure, including the existing `HistoryViews.attach_history` caller.

### One transcript witness owner, live and recorded source members

Make the original `TranscriptReadIdentity` own its live/recorded source contract
through declaration-owned members. Common native/route/bus/coordination/read
revisions, assigned and outcome frontiers, window cursors, content identity and
page bound remain declared once. The live member owns actual `Thread`, inherited
parent/task content and live turn settlement. The recorded member owns only
`ThreadProvenance` plus the attached source identity; it has no turn/admission
authority. This is a proposal to extend the existing identity, not another page
reader or stored snapshot of a live owner.

Migrate acquisition, rebinding, currentness and deferred page read together:

- `Transcripts.capture_page_read/capture_page_window` select the same attached
  recorded source that `thread_transcript_page` already selects.
- `bind_page_read` validates root, selected source, incarnation/aliases and exact
  window against that namespace. A same-name live thread cannot substitute for
  the recorded source; detach/replacement remains a refusal.
- `TranscriptRead.current_identity/read` reacquire that same source and preserve
  both pre/post content fences. All archive routes, wire receipts, publication
  revisions and compaction cursors use the recorded root, not the destination.
- Move the existing live-versus-recorded source selection out of repeated page
  decisions into these owning members. Reuse the existing native/wire merger,
  paging direction, byte budgets, frontier membership and cursor validation.

Do **not** merely annotate `thread` as `ThreadProvenance`: current
`content_thread` reads `parent/task`, and Toad's `OwnerSnapshotConsumer` reads
`identity.thread.turn_state`. `ThreadProvenance` deliberately declares none of
these. The identity's declared wire members must migrate together with
`TranscriptSnapshotUpdate`, `ThreadPresentation`, Toad
`CoordinationTranscriptReader` and `OwnerSnapshotConsumer`. Strict `FieldCodec`
uses the actual encoded declaration and rejects extra fields; a plain subtype
or a trial-decoded union cannot safely substitute for family dispatch.

Live turn settlement remains on the live identity/actual owner contract;
recorded reads cannot manufacture `TurnChangedUpdate`. Published-read fallback
in Toad must retain the original selected source when reacquiring a stale
window. Existing preparation work keys continue to derive from the identity;
there is no new cache or freshness store. The historical sessions screen must
use the same witnessed acquisition when adopting deferred reads, preserving its
selection generation and existing `TranscriptHistory` loader.
