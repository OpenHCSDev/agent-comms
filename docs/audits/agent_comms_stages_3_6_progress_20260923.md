## Contract and trust boundary

The authoritative local single-UID scope is `plans/trust-boundary.md` SHA-256 `b633d7a956269ad3273dcbfb884cd4e0e04b8b822280d5da42850fdbc1715c1a` in the development worktree (not present at the PR base). Ordinary crashes, races, late delivery, lost updates, uncertain provider calls, false success, and autonomous retry **are in scope**. Same-UID forgery/direct internal calls, whole-root rollback, hardware tampering, and hostile second users **are not**. Apply `CLEAN (scope: …)` to a precise stopped-byte slice, `ADVISORY (does not enforce: …)` to cooperative arbitration, and `NON-CLEAN` only to a concrete in-scope failure. A test pass, owner handoff, snapshot, or old-hash review is never a release verdict.

The architecture maintains separate authorities rather than promoting display text to fact:

1. **Stage 3, durable audience:** commit one public bus envelope and a private full-**N** recipient decision sideband in the same fsynced row. Every N member gets an individual selected acceptance or typed `NO_WAKE` observer receipt; only selected **K ≤ N** may claim model work. The frozen send-time audience, original route, and typed decisions cannot be reconstructed from current tags or message-body mentions after a restart.
2. **Stages 4/6, attempts and publication:** reserve a claim-bound CSPRNG input ID before Pi. A live, attempt-bound context-assembly witness is distinct from an RPC ACK, queued prompt, SQLite claim, Pi journal row, assistant stop, provider response ID, and bill. A prepared exact response intent (Tx1) and keyed bus receipt support Tx2 resolution by **reading the existing receipt**, never by resending an uncertain response. Owner turn/incarnation/epoch and registry/SQL fencing serialize stop with append; no automatic replay of uncertain model, tool, or wire side effects.
3. **Stage 5, recovery and UI:** a bounded snapshots-only SQLite reader and owner-only process gateway project evidence to a recovery view; they do not authorize retry, monitor, or writer mutation. Transcript routing must come from typed provenance or a verified safe source, never a header-looking string alone. Toad's UI is a view, not a second coordinator.
4. **Resource claims on envelopes:** a single typed, newline-complete, fsynced bus row is the proposed default-off authority for all-or-nothing file claims/releases and announcement. The earlier O_EXCL bootstrap remains `ADVISORY (does not enforce: raw bash/edit writes or atomic send)`. Marker sequence is a reservation **hint**; verified bus rows are the committed watermark. All claim-bearing reads must share a guarded wire→bus path and re-fsync a complete visible append after an uncertain fsync before exposure.

Default-off is deliberate: **production publication, monitoring, automatic retry, and `SILENT` are OFF**. No old-writer cutover, production private-root marker issuance, automatic uncertain replay, global Pi patch, or compatible pinned Toad deployment is authorized by this ledger.
