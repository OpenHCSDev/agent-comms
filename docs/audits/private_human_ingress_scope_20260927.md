# Private USER ingress — scoped implementation boundary

This draft adds a cooperative local UI-origin `Comms.send_user_message` path for an explicitly marked owner-only private root. It does **not** authenticate one process against another process of the same UID (`plans/trust-boundary.md`); it is not an executable owner, selected-source grant, ACP coding wake, provider authorization, or production route activation.

- Legacy roots continue to use their existing public append. Direct legacy `MessageBus.publish` still refuses marked private roots; generic private USER publication without an internal `HumanOrigin` remains denied.
- The human operation holds the canonical wire lock through USER identity selection and bus publication. The bus lock encloses marker verification, registry/visibility/name/creation/worktree binding, routability, send-time frozen full audience, pure N/K decisions, original public envelope and sideband validation, and one private append. No second bus format or journal is created.
- A successful return is the committed `Message` used for Toad paint. Its initial sideband can be read and accepted into the existing atomic N/K SQL receipt. A repeated same USER message ID found in a committed row is denied before another append. The root baseline is the fresh private protocol marker (`last_seq=0`) with no legacy bus rows; every committed private row is expected to advance its sequence by one. A reservation-only failure can leave no row containing that ID, so human admission additionally requires contiguous verified private bus sequences from 1 and marker high-water equal to the verified last row. Any reserved gap blocks **all** future human sends (same or different ID), even after an agent appends a later row, until an explicit reviewed manual reconciliation path exists. This is a deliberate availability loss, not an idempotency grant for a *new* timestamp/ID.
- A failure after entering private append/reservation raises `HumanInitialUnknownError` with root ID, sequence and message ID; the caller must inspect, never automatically retry or report definite absence. A process killed mid-send might leave an unknown outcome without delivering an exception to its UI; no replay-on-restart is provided. A malformed target or origin rejected before append is a definite denial. UI cancellation does not stop a worker already appending and must never trigger an automatic retry.
- The PR116 legacy retirement guard now wraps USER identity creation and bus publication; a stale old-root Comms object must not append after private route activation. This does **not** fence default-root route selection by a Toad view: Toad must use the separately reviewed PR116 `guard_default_route_write(expected_root)` around its synchronous send, spanning route revalidation and actual write. Explicit `AGENT_COMMS_ROOT` remains an override. A static painted private-root page or core-only send is not mounted interactive cutover acceptance.
- The original core ingress was reviewed at `893b6a7` on draft PR116 `a9e8864`; its isolated integration rebases onto PR116 `f97bf3b` with the outer legacy guard preserved. Neither verdict transfers automatically to this combined head or the newer Toad guarded successor. No production route/install, old-root write, UNKNOWN replay, Toad source change, or selected ACP dispatch occurs.
