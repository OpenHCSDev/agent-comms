# Default-OFF native Pi PID-namespace retirement prototype

Base `1273f0f` (merged PR94) plus local blocker-probe `89fba0b`. This is an **isolated prototype**, not an installed launch or PR95 settlement implementation. No provider credentials, request, live worker/process signal, installed pinned fork mutation, old UNKNOWN retry or PR95 marker clear occurred.

## Mechanism and scope

`native_pi.run_native_pi_turn(..., retirement_identity=None)` preserves the old default behavior. An explicitly provided `RetirementIdentity` selects `native_pi_retirement.spawn_retired_child` on Linux only. Identity includes wire root; exact input ID; stage/claim and full execution/ordinal; canonical owner/recipient lookup, owner PID/incarnation timestamp, SQL generation, admission epoch and turn; source seq/message ID; durable native request-envelope digest; and canonical **preexisting** saved session path. The prototype verifies these value shapes, prompt digest and owner-only prewrite file dev+ino, but **does not itself corroborate the supplied fields against the live coordinator/registry**. PR95 must independently bind them under its own final locks. Fresh-file creation mode intentionally denies.

A trusted Python wrapper arms `PR_SET_PDEATHSIG(SIGKILL)` before `exec(unshare --user --map-root-user --pid --fork --mount-proc --kill-child)`. Namespace PID 1 independently arms its parent-death signal and authenticates over a socketpair using a random nonce. Before dispatch, the parent verifies `SCM_CREDENTIALS` host PID, `/proc/<pid>/status` NSpid ending in 1, parent wrapper PID, distinct PID-namespace inode, and obtains a pidfd. Only then does it send the `start` command. The child inherits the actual native Pi RPC stdin/stdout/stderr pipes; `run_native_pi_turn` uses its existing real parser and, when supplied, isolated raw prompt writer. Child PID 1 remains alive for the whole turn. Errors, cancellation and unsupported containment have no fallback to the old process group.

After the live-correlated terminal input/context proof, cleanup pidfd-kills namespace PID 1, waits for the wrapper and requires the init pidfd readable and host `/proc/<init>` gone. Linux PID-namespace-init death retires descendants even when independent fake RPC/extension/tool groups call `setsid`. The parent verifies the saved session dev+ino unchanged, fsyncs the owner-only session and proof files plus session directory, re-reads exact context evidence, exclusively creates a per-input terminal file, fsyncs it and its parent, and only then returns a nominal one-use in-memory `RetiredNativeInputReceipt`. A visible file after lost fsync/return is **not** authority. The receipt proves neither provider consumption nor PR95 journal settlement, and no production selected caller passes the opt-in argument.

`experiments/native_pi_retirement_compiled_probe.py` discovers a **reviewed disposable** pinned Pi fork with `_trusted_package`, removes all credential-bearing environment keys, prepares the real `NativePiRpcLaunch` with `PI_OFFLINE=1`, starts it in the PID namespace using the new launcher, and sends **only** `get_state`. ```

Exact log: `/dev/shm/native-retirement-compiled-standalone.log` SHA256 `0e1127474c1398bc2107b0fcdbd4107076a3a4cff26bcadb42224331ec82ee5c`. Rootless user namespace maps host owner `ts` to uid 0 but the host-root-owned `/var/tmp` ancestor to overflow uid; the reviewed fork's ancestry check requires each ancestor owned by effective uid or root *inside* its namespace. It denies before `get_state`, correctly returns no receipt, and cannot yet run a real pinned Pi turn in this namespace. Do **not** relax the reviewed native privacy check or treat fake-RPC results as compiled Pi acceptance. An owner-controlled isolated rootfs/idmapped mount plus reviewed fork compatibility would need separate design and source review; macOS and hosts without unprivileged PID namespaces also remain unsupported.
