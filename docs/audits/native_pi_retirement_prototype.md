## Mechanism and scope

`native_pi.run_native_pi_turn(..., retirement_identity=None)` preserves the old default behavior. The former explicitly provided `RetirementIdentity` selected `native_pi_retirement.spawn_retired_child` on Linux only; this is now unconditionally quarantined before dispatch in **both** entrypoints. Identity includes wire root; exact input ID; stage/claim and full execution/ordinal; canonical owner/recipient lookup, owner PID/incarnation timestamp, SQL generation, admission epoch and turn; source seq/message ID; durable native request-envelope digest; and canonical **preexisting** saved session path. The prototype verifies these value shapes, prompt digest and owner-only prewrite file dev+ino, but **does not itself corroborate the supplied fields against the live coordinator/registry**. PR95 must independently bind them under its own final locks. Fresh-file creation mode intentionally denies.

The halted historical mechanism used a Python wrapper to arm `PR_SET_PDEATHSIG(SIGKILL)` before `exec(unshare --user --map-root-user --pid --fork --mount-proc --kill-child)`. Namespace PID 1 independently arms its parent-death signal and authenticates over a socketpair using a random nonce. Before dispatch, the parent verifies `SCM_CREDENTIALS` host PID, `/proc/<pid>/status` NSpid ending in 1, parent wrapper PID, distinct PID-namespace inode, and obtains a pidfd. Only then does it send the `start` command. The child inherits the actual native Pi RPC stdin/stdout/stderr pipes; `run_native_pi_turn` uses its existing real parser and, when supplied, isolated raw prompt writer. Child PID 1 remains alive for the whole turn. Errors, cancellation and unsupported containment have no fallback to the old process group.

The historical post-proof cleanup *intended* to pidfd-kill namespace PID 1, wait for the wrapper and require the init pidfd readable and host `/proc/<init>` gone. Linux PID-namespace-init death retires descendants even when independent fake RPC/extension/tool groups call `setsid`. The historical parent code then checked saved dev+ino, fsynced the owner-only session and proof files plus session directory, re-read context evidence, exclusively created a per-input terminal file, fsynced it and its parent, and returned a nominal one-use in-memory `RetiredNativeInputReceipt`. **That receipt is not authoritative**: numeric SCM_CREDENTIALS PID→pidfd opening was not identity-safe. A visible file after lost fsync/return is **not** authority. The receipt proves neither provider consumption nor PR95 journal settlement, and no production selected caller passes the opt-in argument.
