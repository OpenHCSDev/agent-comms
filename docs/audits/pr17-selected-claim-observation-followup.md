# Selected claim observation follow-up (local, not PR17 activation)

Base: merged `main` `db011def46028ea174bdf158a1da179277ff5da7`; PR17 itself merged at `a00d0e7c716750bd9bbd6b8bf9c456d0d3e80f52`. This slice is **read-only** and has no model/provider, write, release, replay, or production activation route.

`observe_selected_resource_claim` checks a typed `WakeAdmission` against the committed private initial row, sealed selected receipt, current owner incarnation/turn/generation, current SQL execution and attempt, and the complete guarded durable bus claim projection. It then compares the canonical existing resource with the exact claim admission, owner incarnation, and recorded resource generation. It returns an immutable, source-cited **observation**, not an authorization. Missing, foreign, released, settled, stopped, stale, malformed, or over-budget observations deny. Guarded bus/registry read errors, including a crash-incomplete tail discovered during the bus lock's pre-yield validation, yield a bounded source-cited unavailable denial rather than restoring an old claim. Unexpected programming errors remain visible. A post-append lost result may be observed from the complete durable row; this function never resends or settles the UNKNOWN caller operation. Independent explicit claims by no-wake observers remain valid; they appear as a conflict for a selected observer only when the paths actually match. The optional wake-frame claim snapshot is pure formatting of a previously checked observation; the one-shot private runner supplies no resource-specific snapshot and performs no new scan in its delivery hot path.

The function measures elapsed time, lock acquisition wait, approximate lock-held time until result construction, and the second complete projection scan. The initial-row search is also a guarded full scan. The 250 ms budget is **post-hoc fail-closed for this optional observation only**: an exclusive `flock` wait or in-progress scan cannot be interrupted by this budget. It therefore does **not** satisfy the original 250 ms delivery deadline, cannot run synchronously in ordinary ACP/original delivery, and is not a solution to 10/150-thread sustained-load scalability. A later incremental proven-index/cursor path must be separately designed and reviewed. The observation expires as soon as locks are released; it must never be used as a pre-write fence.

## Separate bounded in-lock write adapter prerequisites (not implemented)

A genuine mediated edit must revalidate selected receipt, owner turn, execution/attempt, *current* bus claim owner/incarnation/generation and canonical path while holding the common wire→bus→registry→SQL serialization boundary **through the actual I/O and durable result**; a check followed by unlocked writing is a TOCTOU, not enforcement. Before implementation, bound payload size and path count, define support for only existing regular singly-linked non-symlink files and decide inode/rename/ABA policy; stage content outside shared locks without calling a provider, then revalidate inside locks. Specify atomic replacement versus in-place semantics, file mode/ownership preservation, fsync of replacement and parent, fault-after-replace UNKNOWN visibility and exact operation-ID reconciliation, and crash before/after commit tests. Bound lock acquisition, scan, payload/fsync duration and bus ingress impact; an unbounded full-bus scan or slow disk write under wire→bus→registry locks is not acceptable. Document that `bash`, child processes, extensions, external editors, create/delete/rename and different worktrees are outside this narrow adapter; no universal file enforcement claim follows.
