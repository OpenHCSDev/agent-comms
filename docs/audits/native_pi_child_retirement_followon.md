# Native Pi child retirement follow-on (disposable proof, not a terminal receipt)

Base: merged PR94 `1273f0f508cf704c741f575d9e886a266b25088b`. Scope: isolated provider-free fake processes on Linux. No installed/live/provider process, historical input, PR95 tree, or PR94 merged source was changed.

## Verdict: BLOCKED for an authoritative returned receipt on the current native launch

`src/agent_comms/native_pi.py:532-540` launches one `node` child with `start_new_session=True`. Cleanup at lines 673-703 sends TERM/KILL to `process.pid`'s **process group** and waits for that one process. A child that calls `setsid()` leaves the group. Its exit and any further descendants are not attested by `process.wait()`. Successful `NativeTurnResult` at line 668 is conditional on protocol/journal checks but not on complete descendant retirement. There is no dedicated PID namespace, cgroup, pidfd-backed child-incarnation fence or parent-fsynced terminal-retirement receipt in this path.

The session file is learned from `get_state.sessionFile` only after launch (`native_pi.py:588-592`), and `_read_private_file` does `lstat` followed by a separate path open (`native_pi.py:101-124`); no prewrite immutable session dev+ino or explicit fresh-file creation identity is supplied to the raw writer. The reserved input/owner/source/binding checks in `coordinated_runtime.py::_native_send_boundary` (~293-456) protect bytes admitted to stdin, not post-send child ancestry or a terminal result. `native_source_cursor` is later source/native-proof metadata, never this receipt.

Therefore **do not construct, persist, return, or accept a positive retirement token** from current `killpg`+leader wait, RPC ACK, completed text, journal visibility or current cursor. A fail-closed no-receipt result leaves PR95's private UNKNOWN marker unchanged. The separately needed journal terminal COMMIT+parent fsync and actual model/provider semantics remain outside this probe.

## Disposable contrast experiment

`experiments/native_retirement_probe.py` uses a *local subprocess controller* marked as a Linux child subreaper. Peer PID credentials come from `SCM_CREDENTIALS`; individual disposable child identities are held as pidfds. Its process-group baseline starts a descendant which calls `setsid`: killing and joining the group leader leaves that descendant live, which is then killed by its verified pidfd and reaped. Its contrast launches an isolated PID namespace with `unshare --user --map-root-user --pid --fork --mount-proc --kill-child`; host `/proc/<init>/status` attests inner `NSpid: <host> 1`, and both a fake escaped RPC child and its independently `setsid`-escaped tool child have the **same** PID namespace inode as init but different process groups. After a pidfd-directed kill of namespace PID 1, the wrapper exits and both fake descendants' pidfds become readable; neither remains in `/proc` (kernel reaped). The probe arms parent-death signals on the disposable launcher/init and gives fakes a bounded lifetime tied to the controller pidfd. It signals *only* these spawned fakes. Three sequential local runs each reported the same control and contrast result; no probe process remained.

Commands: `python experiments/native_retirement_probe.py`, or the bounded `timeout --signal=KILL 35 python experiments/native_retirement_probe.py`. Logs: `/dev/shm/native-retirement-probe-{1,2,3}.log`, SHA256 respectively `39681585a18dd6caee9fba54d743d9f21d253cba092a21dc907e3ddac990412c`, `f478b7ae6db57db54ed1d6f2d1d562a62dd83aa82b43830e7fb47405dfe0759d`, `a9e4d4d8fbcbd4675a88658685a9d9a5bc7e4351a986f389525c4aeab88dbaea`. This is a kernel-containment feasibility result for these fake descendants **only**—not proof that real Pi, extensions, tools or external RPC daemons are launched in that namespace. `/sys/fs/cgroup` is read-only on this host; unprivileged user+PID namespaces were available here, not proven across platforms.

## Required architecture before a positive one-use result can be considered

1. Before input reservation/dispatch, create a dedicated, fresh, verifiably isolated child incarnation. A trusted launcher must return a stable pidfd/namespace identity and prove its init is PID 1 there. Arm a watchdog before any prompt bytes; close the parent-death and launcher-failure windows. Deny on unavailable PID namespaces/unsupported platforms; no fallback to process-group join. Ensure every permitted Pi/RPC/extension/tool process is confined there; prohibit or separately account for external daemon delegation and namespace escape. Test cancellation, parent crash and adversarial `setsid`/nested children with no surviving descendants.
2. Bind the prewrite durable input reservation and prompt digest to exact wire root, source seq/message ID, stage/claim, execution+ordinal when full, canonical owner/lookup, SQL generation and registry admission epoch/turn. Bind a *validated* native session ID and canonical saved session path to prewrite dev+ino (or an explicitly attested fresh-file creation identity) without relying on late path-only `get_state` observations. A native protocol ACK or context row is not a retirement receipt.
3. After the exact terminal input/context correlation, retire/kill namespace init as needed, verify pidfd exit plus complete namespace descendant death/reap under a finite bound, then durably COMMIT/fsync the terminal journal and its parent. Only a **one-use returned** exact-identity receipt may be considered by PR95's independent locked comparison; lost return, timeout, error, cancellation, parent death, unknown child membership, or visible terminal row after UNKNOWN yields no receipt and cannot clear UNKNOWN. Proof of provider consumption is a separate contract.

Until these gates are implemented and independently reviewed on actual launch bytes, the positive PR95 private settlement path is blocked, not merely missing a convenient test fixture.
