# Push-at-wake context with selected N/K resource admission

Status: **draft integration, not production activation or file-write authority**. This combines the proposed prompt-injected harness with the selected-wake/resource-claim work already on PR #17. The agent should *learn* current work and ownership from an authoritative projection at wake, without remembering an `accept_work` command. Durable receipt checks remain the authority at a mutation boundary; injected words do not grant a model turn, a claim, a response route, or a file write. No live provider is needed for implementation or tests.

## Current PR implementation (narrow)

- `send_initial_cohort` commits a private-root original message and frozen audience; `accept_initial_cohort` seals N delivery receipts and K selected wake claims in SQLite. No-wake members have delivery receipts but no model input. The one-shot foreground runner handles one selected claim on a marked private `/var/tmp` root. This is **not** ordinary `comms_send` delivery.
- A versioned `WakeAdmission` can be verified against the committed original, sealed selected claim, live owner generation and turn, execution, and unfinished attempt. `publish_selected_resource_claim` test-gates one existing-file claim in a durable bus row. A post-append lost acknowledgement is UNKNOWN, not grounds for resending. This operation is **not** a native write authorization, a coordinator admission receipt, or a normal channel-send bridge.
- The private runner now renders a small read-only wake frame from the **already verified selected** original and claim: bounded triage says engage only if relevant and has no response obligation; FULL (including triage that engaged) cites its pending exact response obligation. The original message stays separately identified as untrusted JSON. No-wake members produce no frame or model call. This slice adds no extra wire scan, exclusive-lock read, cursor, or provider launch; the runner remains one-shot and uses a no-tools native turn.
- `Comms.send_message(..., claims=..., releases=...)` has existing bus-authoritative resource transitions. The normal agent-facing `comms_send` tool has no claim parameters. `tests/test_claim_admission_baseline.py` intentionally shows a no-wake observer can still make an **independent explicit** file claim; the frame does not change that rule.

## Combined target contract

1. **Original and selected receipt.** Resolve each message's canonical audience once. The committed bus row and sealed N/K receipts decide visibility and wake eligibility. Trusted metadata, not message body, `info` type, or read ACK, determines PASSIVE, BOUNDED_TRIAGE or FULL. A selected wake must verify stable recipient lookup, owner incarnation, claim ID/revision, original sequence, and exact policy before running. PASSIVE does not start a model; bounded triage does not silently become FULL.
2. **Push awareness, not authority.** At an eligible wake inject a concise, source-cited view of new messages and relevant current state. FULL means "this is yours"; bounded triage means "engage only if it concerns you"; PASSIVE is readable in channel but not a model launch. Keep visibility, read acknowledgment, wake eligibility, response authority, and file ownership distinct. The first private-root slice above frames only the selected original and its exact obligation. It is not the later all-channel injection service.
3. **Decision and obligation projections (future).** Introduce owner-authored, scoped, stable-ID decisions and owner-approved exact-quote DM proposals. Supersession appends a new decision; record outcomes (`accepted`, `ignored`, `contradicted`, `refined`, `replaced`) and overturned review verdicts rather than editing history. Scope defines eligibility; relevance may reorder but never drop an in-force decision within a *successfully assembled* frame. Give decisions a stable cached prefix only after native session semantics are checked. Project every open response obligation, with owner-directed obligations first; a direct reply referencing its source sequence, explicit decline, or declared SILENT disposition settles it. The current `ResponseObligation` belongs only to a selected wire execution and does **not** yet implement arbitrary direct-message obligations.
4. **Supersession and task heads (future).** A versioned wire `supersedes` relation labels or suppresses an older message not yet acted upon; show a successor with the original sequence it replaced. Inject a task head only when a durable task→commit authority exists. Never infer supersession from prose or a local worktree guess.
5. **Claim awareness plus action backstop.** Inject relevant current resource owners before work, but do not fabricate ownership because the agent saw text. The native *mediated* pre-write boundary must verify current selected-wake and owner identity, canonicalize the existing file, check the bus-authoritative projection, and either acquire/reuse the exact generation or deny before I/O with owner, source sequence and next action. Existing selected-claim publication is a foundation, **not this gate**. Old independent explicit claims remain valid until a precise cohort/resource scope is designed; do not globally invert the baseline test or treat all unselected recipients as prohibited from unrelated work.
6. **Crash and release.** The complete verified bus row is authoritative for resource ownership; an idempotent coordinator admission receipt, if used, follows its commit and reconciles from that row. JSONL append and SQLite transaction are not atomic together. An uncertain append is never blindly resent, a model input is never automatically replayed, and a read ACK is not a claim receipt. Release only the exact owner-incarnation and resource generation after verified work; rename is not replacement, stop/replacement cannot inherit uncertain work.
7. **Cooperative enforcement boundary.** A native edit/write gate can be a useful backstop, not proof of hard filesystem enforcement: `bash`, child processes, extensions and external editors can bypass it. Production-strength protection requires reviewed worktree/filesystem mediation of create, rename and delete too. Separate per-agent worktrees *may* reduce direct clobbering, but must be verified as isolated; upstream merge conflicts and unmediated writes remain. Never call a frame or a tool-only gate universal enforcement.

## Scale and failure contract for later injection slices

An injection service must derive a rebuildable, incremental projection from committed wire rows, not rescan the bus under an exclusive lock for every wake or once per member. A SQLite WAL read model is proposed so multiple recipients can read without serializing on `_store_lock`; the JSONL bus remains the authority. Filter by durable recipient, task, channels and tags; use a per-recipient last-**proven-injected** cursor, a fixed wake budget, and changed rows only. Binding in-scope decisions and open obligations cannot be silently truncated on a successful frame. Nonbinding triage/context may be ranked, summarized and counted as overflow. Measure build time, injected size and delivery p99 at 10 and 150 threads.

A slow or unavailable projection must not stall original delivery. Start with a 250 ms build deadline; on overrun, deliver the original alone, log the omitted supplement, **do not advance the injection cursor**, and do not treat missing text as discharged or as action authority. Work whose safety depends on a current decision or selected claim must be denied by its native authority check even if a frame was omitted. Do not conflate a cursor/ACK with proof that Pi accepted an input; ambiguous native acceptance requires explicit disposition, not a blind replay.

## Implementation slices and no-provider tests

1. **Done only for private selected N/K:** read-only selected-frame formatting tied to the verified original, wake mode and exact pending response obligation; fake native Pi tests assert triage/FULL wording, absent triage obligation, and no-wake zero model calls. This slice has no claim awareness or ordinary-send integration.
2. **Next:** a bounded, versioned derived projection with append update, WAL read, scoped delta/cursor, timeout and stress tests, with no full wire scan at wake. Design the native injection point and stable-prefix cache semantics before claiming decisions are in every model context.
3. **Then:** owner decision/proposal capture, scope, supersession/outcomes; arbitrary direct/owner obligation projection and discharge; stale task-head/supersession labels. Test ranked low-score decisions are retained and timeout cannot silently mark them delivered.
4. **Then:** relevant claim awareness and a scoped cohort resource-eligibility rule preserving unrelated legacy claims; a crash-safe coordinator receipt and a disposable fake native pre-write edit adapter. Test no-wake direct admission denial, competing selected owners, before/after append and receipt faults, owner rename/stop/replacement, exact release, and unsupported shell writes. Wire ordinary channel sends and real mediated write paths only after these contracts are reviewed.

One focused commit and no-provider tests per slice; independently review the *combined exact bytes* for named admission and uncertainty findings before any activation. Green general CI or a passing proposal is not acceptance of the unimplemented slices. Merged sidebar route-count projection is not claim authority. No paid-provider run is authorized here.
