## Two disjoint paths

- Leave `coordinated_runtime.run_one_sealed_claim` and its **one-shot** `root/native-sessions/<recipient_lookup>` check untouched. Its transient native Pi `--no-tools` result is not an ACP coding turn.
- A new, explicitly enabled *persistent ACP owner* selector may only adopt an **ACP-acquired canonical registry turn**. It may not call `Comms.begin_turn` or `claim_live_turn_with_admission` a second time, borrow another owner's active turn, start or fork Pi, or fall back to one-shot/legacy ACK. ACP must hold one turn-claim fence with exact `name,created_at,pid,admission_generation,turn_id,turn_generation`; adoption CAS compares the same FULL row and current execution/claim/generation. A local session mutex and cross-process saved-session writer fence prevent another ACP prompt in that child; they do not replace durable claim CAS.

## Exact incumbent session binding

Before any source engagement/reservation, ACP must already retain a live `PersistentPiSession` belonging to the same ACP session and worktree, not construct a fresh instance. Its process PID/handle, launch key (including model/thinking arguments), `session_id`, exact `session_file`, and file+input-proof revision must match the registered owner and a previously enrolled owner-approved session root. The latter is an **exact lexical private directory/file authority**, not an arbitrary `Path.resolve()`/recipient-wide scan. Reject `..`, symlinked components, changed owner/mode/link count/device/inode, mismatched parent or changed revision; pin the file/directory identity through final raw send. A saved path alone never enrolls an old/marked/UNKNOWN session. A live `get_state` response with exact request ID must match the same child/session ID/file; separate SDK processes and get_commands cannot attest it. No implicit relocation into `root/native-sessions` and no relaxation of the one-shot guard.

The tool-capable path requires a separately reviewed copied-Pi **same-child** capability witness: active model tools (names + full definitions/schema/source provenance digest), loaded extension hooks/identity/errors, effective settings/resource generations, model and thinking level. Compare with an independently approved owner-bound coding profile both before reservation and at send; missing/mismatched witness is hard no-STARTED. Pre-/post-turn snapshots alone cannot guard a dynamic mid-turn tool replacement: the copied child must freeze an input-bound epoch or deny each model/tool execution before side effects upon drift. Until that source patch and review exist, readiness is false.

## One irreversible source/claim/input path

The private first-source, marked-path and active owner checks precede claim selection. Resolve an original committed initial and exact sealed FULL claim (never text/preview as authority). The ACP turn fence, source ID/sequence, audience/recipient lookup, claim ID/revision, execution/attempt fence, and one random `input_id` are bound in SQL with an input-ID FK and FULL-row CAS before any raw byte. A crash after reservation yields explicit UNKNOWN, not a fresh ID. A second attachment, same ID from another object/process, changed owner/goal/turn, or already-marked session is denied before the first byte. Tool calls must be bound and revoked per input, session, owner turn and execution attempt; no tool side effect may derive authority from a synthetic `tool_execution_start` event.

Use the **same** reviewed PR95 raw-first journal/exclusion as other saved-session writers, not a parallel ledger. Acquire the outer saved-session writer/child locks **before** the canonical wire→bus→registry→SQL→journal order (without awaiting RPC under those inner locks). Persist a selected UNKNOWN marker *before* first os.write; hold raw exclusion through all bytes. A false/non-None boundary grant denies bytes; partial write, cancellation, failed fsync or post-byte exception stays UNKNOWN with no retry. A live exact input/context event pair plus private session/journal corroboration is necessary for context disposition but is not by itself final-send authority. Final publish must CAS the same owner/turn/claim/attempt and preserve a durable response/cursor; ACP reconnect reads this row, not a legacy ACK. No premature active-turn finish, duplicate response or replacement process.

## Negative review matrix before any runnable bridge

1. Wrong directory, symlink in file or parent, path traversal, file replacement/inode/revision or proof-journal change, session ID/PID/worktree/model/profile change: zero raw selected bytes; no spawn.
2. Owner stopped/restarted, renamed, goal/turn changed, two registry turns, ACP/controller disconnect, or second attach/process: no claim mutation or raw byte; the active turn is not borrowed. Recheck after reservation and immediately at raw writer boundary.
3. First-source not enrolled, marked/UNKNOWN path, altered audience/claim FULL row, duplicate input ID, concurrent ordinary/selected writer: deny before first byte; no second journal.
4. Boundary False/True, admission exception, partial pipe write, cancellation and post-byte failure: typed UNKNOWN/no replay and child revoked; tests distinguish zero-byte refusal from possible-byte uncertainty without treating either as retryable.
5. Missing/extra tool, changed tool schema/source, extension hook, settings generation, model or thinking level, including a mid-turn mutation before a tool: hard no-STARTED or pre-side-effect revocation. No fake Pi event or PID equality substitutes for a same-child witness.

Acceptance requires independent substantive/security review of an exact integration head, then separate authority for disposable-root provider/live proof (ordinary→one selected safe isolated-worktree tool call→durable disposition→ACP reconnect/cursor→second ordinary prompt in the *same* child, plus forced UNKNOWN without replay). This design does not authorize that run.
