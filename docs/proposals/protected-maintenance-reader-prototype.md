# Protected maintenance reader prototype — NOT deployed

This branch is a **default-OFF source prototype** based on reviewed core PR109 (`08a86a0`, merged as `a822a8d`). The existing `MaintenanceBarrier(registry_path)` API and all default-OFF behavior remain unchanged. A caller may explicitly construct `MaintenanceBarrier(registry_path, protected_config_path=...)` for isolated review. No production caller supplies this argument; no phase writer, broker, operator API, host unit, Toad bridge, or live activation is included.

The optional reader expects a root-owned 0644 single-link config at `/etc/agent-comms/maintenance/<32-lowercase-hex-root-id>.json` with root ID, canonical wire path, required-protection flag and reader GID. It requires root-owned non-group/other-writable ancestors, an exact root:reader-group 0750 directory `/var/lib/agent-comms/maintenance/<id>/`, and regular root:reader-group 0640 single-link `enabled` and `state.json` files. All are read with no-follow opens; mismatch, missing config, missing pair, corruption, symlink, wrong owner/mode/group, or inconsistent generation closes admission. It **never falls back** to user-owned `.maintenance-enabled`/`.maintenance-state` once an explicit protected config path was selected. There is no mutation method. Wire/registry locks and the synchronous `admit_ingress()` API are unchanged.

Current uid1000 has unrestricted passwordless sudo, so none of these file checks is an authority boundary on this host. The tests simulate protected ownership with the current UID/GID and disposable trust anchors under pytest temporary directories. They prove only parser/fallback behavior, not authenticated operator or old-client exclusion. The optional path argument is not a secure deployment selector if read from a worker environment or attacker-controlled input. A separate exact-head reviewed migration must bind all worker/ACP/native/Toad constructors to one root-owned launch policy and protected wire root, not allow the old default-OFF constructor alongside a configured instance, and supply a root-owned broker, crash-safe generation CAS/ledger and approved old-client exclusion.

Canonical proposed host contract: `/dev/shm/comms-steering-old-import-prototype-20260926/RECONCILED-HOST-CONTRACT-DRAFT.md`. Further cost and risks: current sudo authority must be contracted; an old uid1000 process with a retained provider connection cannot be stopped by a new-code check, and a simple UID nft OUTPUT rule cannot prove all proxy/FD/namespace egress routes. Paired exact-artifact rollback must keep the gate CLOSED and old clients excluded, never automatically restore uid1000 sudo or live dispatch. No source-only test establishes production readiness.
