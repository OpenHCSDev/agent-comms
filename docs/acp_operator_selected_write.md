# Private N/K ACP operator-preplanned selected-file write (partial)

**Default OFF; operator-supplied bytes; advisory/partial, not agent-selected tool
completion or production admission.** This public ACP path is separate from
Pi-facing selected tools. It does **not** enable tools/extensions in native Pi,
change its `--no-tools --no-extensions` launch, or intercept shell/edit/child
writes. Ordinary sessions, public roots, and unrelated private workers cannot
opt in with ACP metadata alone. This is not a filesystem security boundary.

On an attached private N/K owner ACP session configured with an exact matching
`AGENT_COMMS_PRIVATE_NK_WIRE_ROOT_ID` and
`AGENT_COMMS_PRIVATE_NK_NATIVE_PACKAGE`, an operator may issue an **empty**
`session/prompt` with precisely this `field_meta` (camelCase on ACP wire):

```json
{
  "agentComms": {
    "selectedExistingFileWrite": {
      "sourceSeq": 41,
      "sourceMessageId": "the-exact-committed-message-id",
      "resource": "/physical/owner/worktree/existing-file.txt",
      "contents": "bounded UTF-8 replacement bytes"
    }
  }
}
```

No prompt content, other `agentComms` options, inferred source, or model-supplied
payload is accepted. The owner process, not the attaching ACP process, verifies
its live pid/incarnation/epoch, matching private claim root, committed source
identity, and exactly one sealed selected FULL_PENDING K for itself. It
canonicalizes a singly-linked, regular **existing** file inside its physical
worktree, bounds contents to 1 MiB, and fsyncs a mode-0600 one-shot plan and
its mode-0700 directory. `accepted_not_applied` means **only** that intent was
durably admitted *before dispatch*; it does not grant a write or record a model
result. Duplicate submissions, even after a lost acknowledgment or uncertain
fsync, never overwrite the operation. If dispatch already began, admission
fails instead of retroactively influencing a turn; send and operator admission
are not one atomic action. There is no implicit fallback or automatic retry.

The selected runner loads this plan after starting its exact attempt; the
original attaching ACP controller must still be connected at load **and**
after the terminal native result. A process crash loses the ephemeral
controller binding, so even a surviving accepted journal cannot be replayed
on reconnect. Wrong source, selected K, root, owner, epoch, ordinal, stale
owner turn, observer, changed resource path, or controller fail closed. Native
Pi still runs without tools. Only after the **independently verified** native
FULL result and bound input/context proof does the owner derive `WakeAdmission`
from live source/K/attempt/turn/epoch, publish an owner claim, and invoke the
existing `write_selected_claimed_file` for the preplanned bytes. The operation
ID is generated by the owner when accepting intent, not by ACP/model input.
The fsynced file write does not imply goal/input completion. A failure after
claim publication or mutation is **UNKNOWN** and is never auto-reissued;
inspect durable claim, native input, plan, and file state manually.

Provider-free tests use disposable private roots, test-only fake authenticated
native results and a second-PID real worker/ACP owner socket. They prove the
ACP proxy reaches the owner but **not** live provider output or production
filesystem isolation. A test fixture deliberately holds dispatch to admit a
predispatch plan deterministically; a busy owner can reject the request.
Observer, wrong source/root, duplicate/ambiguous fsync, native failure,
controller reconnect, and lost owner-process binding cases refuse mutation.
None of this authorizes production cutover, privileged host activation,
old-client exclusion, UNKNOWN replay, or a public Pi tool. See
`scoped_mediated_file_write.md` for the underlying narrow explicit write API.
