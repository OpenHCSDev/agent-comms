## Missing behavior

The current `Question` and `ScoreView` score exact answers, but the report mixes
all questions into recall totals. It cannot distinguish remembered identifiers
from preserved prohibitions, retained valid alternatives and valid actions after
a goal changes. The CLI also hardcodes the coding trace, so a frozen research or
long-running-goal trace cannot use the existing recorded-native receiver.

Extend these existing measurement owners: questions declare their measurement
category, and the same score views derive category totals from their original
question/outcome pairs. A frozen scenario file is decoded once by FieldCodec
into `RecallScenario`; export and native scoring use that same object. Add authored
research and goal traces with three source cuts and held-out distinction probes.
Expected answers and categories remain outside provider probe text.

This is evaluation source, not a second Decision/Constraint store. Original
runtime retained facts and journal linkage still come from `RecordedNativeProbe`
and `RecordedNativeCheckpoint`. These authored traces cannot establish runtime
revision mass, final provider prompt presence, matched cost/latency margins or a
default flip. Those remain explicit S4 acceptance work.

Source ownership and complete caller migration come first. One final sanity
batch checks frozen trace decoding/export/scoring and the existing recorded
native consumer. No new paid or public input, matched experiment, provider,
launcher, runtime policy or store is introduced.
