## Missing behavior

The current `Question` and `ScoreView` score exact answers, but the report mixes
all questions into recall totals. It cannot distinguish remembered identifiers
from preserved prohibitions, retained valid alternatives and valid actions after
a goal changes. The CLI also hardcodes the coding trace, so a frozen research or
long-running-goal trace cannot use the existing recorded-native receiver.

Extend these existing measurement owners: questions declare their measurement
category, and the same score views derive category totals from their original
question/outcome pairs. A frozen scenario file is decoded once by FieldCodec
into `RecallScenario`; export and native scoring use that same object. Add authored
research and goal traces with three source cuts and held-out distinction probes.
Expected answers and categories remain outside provider probe text.

This is evaluation source, not a second Decision/Constraint store. Original
runtime retained facts and journal linkage still come from `RecordedNativeProbe`
and `RecordedNativeCheckpoint`. These authored traces cannot establish runtime
revision mass, final provider prompt presence, matched cost/latency margins or a
default flip. Those remain explicit S4 acceptance work.

Source ownership and complete caller migration come first. One final sanity
batch checks frozen trace decoding/export/scoring and the existing recorded
native consumer. No new paid or public input, matched experiment, provider,
launcher, runtime policy or store is introduced.

## Implemented

`Question` keeps the frozen expected/stale/source fields and now declares its
measurement label. Labels supply no alternative scoring policy. `ScoreView`
owns one total algorithm; `ScoredRound` and `ScoredScenario` preserve original
question/outcome pairs instead of discarding the question at aggregation. Whole
report and per-category totals use that algorithm. No count is accepted from a
caller or persisted beside an outcome (IMPL-5/IDEN-1).

`RecallScenario.read` uses the existing strict JSON hook and FieldCodec; its
rounds and questions refuse duplicate identities and absent oracle coordinates.
The CLI accepts `--scenario-file`, then uses that same instance for export,
answers and original native probes (BOUND-2). No scenario roster, codec subclass,
native launcher or production source changed. The existing hardcoded coding
trace remains the default authored input, rather than a second scoring path.

The research trace retains a held-out prohibition while changing a Unicode
manifest path and revisiting a valid rejected control. The goal trace changes
the goal/ticket while preserving UNKNOWN input and distinguishing a distinct
authorized action from replay. Each has three cumulative source cuts. The
frozen oracle is never exported to a provider: only question IDs/prompts are.

Previously approved actions become stale after a correction; never-authorized
actions fail exact scoring without being mislabeled historical authority. These
scores measure answers, not actual task execution or verified Decision drift.
