## Working runner

`--recorded-run` decodes the existing RecordedNativeProbes declaration, now with
`rounds` and `checkpoints` maps keyed by frozen round IDs. Cuts are visited in the
scenario's order, using one borrowed NativeEvidenceRead for the run. A repeated
cut, another session or a non-ancestor cut refuses. Checkpoints can be measured
without a recall probe; missing answers retain the question denominator.
For a probed round, its checkpoint belongs only on RecordedNativeProbe. The
`checkpoints` map contains unprobed cuts; overlapping keys reject rather than
maintaining two matching references.

Each checkpoint still uses the original selected request, managed entry and
CompactionOperation coverage/link checks. Summary usage comes directly from
NativeSummaryPayload.usage, already covered by its verified metadata digest.
Absent usage is unavailable. Explicit zeros remain recorded zeros; neither
establishes cache savings or raw provider cache behavior.

Optional `registry_scope` is FileProvenance pointing to an original captured
RegistryDocument. The document supplies its existing snapshot; no snapshot codec
or copied registry shape is added. `wire` points to its original certified publication source.
Revision measurement corroborates each authored message against that source,
then calls RetainedTaskFacts.current_authored_lineages and the original task
scope/selected_sources behavior. It compares constraints and Decisions separately;
loss retains the prior denominator. Snapshots must be original captures, not a
new observation passed off as a past cut. Missing captures remain unevaluated.
The runner does not confer historical update authority or recreate admissions.

Optional probe `sdk_context` and `context_manifest` are FileProvenance references.
The original NativeContextData/ContextManifest declarations decode them. Segment
bytes, manifests, native identity and NativeProvenance must match the original
NativeContextProof. Exact retained-envelope presence measures the recorded SDK
input only; final transport transformations remain unevaluated. Probe usage comes
from every original assistant completion in the input-to-answer branch, including
tool-call steps. RecordedNativeProbe owns this `model_steps` projection; the
final-only answer_usage projection is deleted. Question/ScoreView still own separate
recall, prohibition, alternative and action scores.
