# PR95 selected first-source startup (default OFF)

This is a bounded **partial** first-source provenance gate, not selected dispatch or
provider permission. The prior frozen baseline is `3d26fe5`. Ordinary legacy
sessions remain ineligible for selected summary; every raw input still enters
UNKNOWN before its first pipe byte and cannot be retired by an ACK or result.

Explicit local enrollment creates a new owner-only O_EXCL v3 saved file and
fsyncs file and parent before returning its creator-process token. Only a
supported `low` or `high` selection writes the selected-only denial marker in
that header, followed by a model-change and thinking-level-change bootstrap.
The token attests header and complete bootstrap-prefix hash, saved dev+ino,
size and bootstrap leaf. A path-only reopen of a marked file (including a copy
or hardlink) is denied before CLI spawn, whether or not a message exists. No
selected continuation/reopen protocol is implemented yet.

The source CLI path is **hard-disabled** in `_require_reviewed_selected_source_cli`.
Fake-RPC tests temporarily override that guard; production never does. Its
candidate selected-only environment is built from a minimal fixed allowlist,
with no inherited credential/proxy variables, plus the copied CLI's explicit
`AGENT_COMMS_SELECTED_SOURCE_COPY=1` marker. That marker's launch integration
needs separate PR94 review. An independently reviewed copied-CLI builtin-path
exclusion alone does not clear transitive startup or terminal authority; a
later change must replace the hard denial with a verified artifact gate. Its
first launch must pass explicit static `--provider`, `--model`, and `--thinking`
plus the private resource-disabling flags, then require an exact pre-input
`get_state`: enrolled session ID/path, static model, matching runtime level,
zero messages/pending work, and idle state. Pinned Pi appends *exactly two*
initial model/thinking metadata entries on zero-message startup. The adapter
accepts only those two chained rows on the original inode and bootstrap
prefix, fsyncs their file, and rebinds the resulting five-field revision.
The owner-locked raw writer repeats that check against the same revision
before reserving UNKNOWN and writing any raw prompt bytes. Extra/message,
partial, duplicate-key, or mutated rows deny the send.

The verified Pi `buildSessionContext()` snapshot derives source-selected
provider/model/level solely from the saved branch and declines unsupported
`off`; it is not evidence that a first prompt ran at that level absent the
runtime preflight above. Tests use fake RPC/transport and copied read-only
SessionManager only. They do **not** prove immutable transitive CLI imports,
no-second-attach, same-UID containment, provider credential provenance,
authoritative descendant retirement, or cross-store atomicity. Actual selected
CLI execution, selected dispatch, provider use, UNKNOWN settlement, activation,
and PR95 merge remain prohibited pending separate exact-head review and PR94
terminal authority.
