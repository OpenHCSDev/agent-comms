**Why:** a requirement is fixed before any representation is chosen; skipping the nominal type or the parent removes none of it, so every pair the declared lattice does not derive is restated by some consumer (paper1 Corollary 4.10), and no helper, forwarder or generator lowers that count (Theorem 4.6) while multiple parents take it to zero wherever needs cross (Proposition 4.2, Corollary 4.12). Tristan, 2026-10-20: "inheritance = factoring and factoring = slop genocide. MI = compositional factoring."

- **Inheritance as much as we can.** A helper object, forwarder, delegate attribute, `*Service` or manager is a missing parent class. Capabilities are mixins composed by the MRO; overlapping capabilities are multiple parents. Inheriting two classes is never a defect. "Wiring in several places" (one check in several methods, one value built at several sites, a parameter threaded through call sites) is the same missing parent: declare the base or mixin (`declared_name=None` for an intermediate) and override only the difference. Tristan, 2026-11-02: "If it needs wiring in two places sound like ur not using inheritance"; "Inheritance isn't an opinion". Coupling to the declaration that guarantees correctness is useful, not a defect to route around. Tristan, 2026-11-07: "coupling isn't inherently bad. coupled to correctenss is good".
- **Under-abstracted is not "avoiding abstraction".** R_req = (H \ U) ∪ dom φ: shrinking the lattice grows the outside routes by the same pairs. A declaration costs one edit per new requirement; an unnamed node is paid per pair on every update (Theorem 4.14, Corollary 6.2). Structural probes admit unwanted members (Proposition 3.3); hand-kept string keys need χ−1 maintained names (Theorem 3.2). Tristan: "under abstracted, is not avoiding abstraction. It's just not encoding it correctly … you break the lattice".
- **Branches select nothing.** Any `if`, `isinstance`, kind string, flag, `None` check, roster or dict keyed by kind that selects behaviour is slop unless it is leaf arithmetic. The fix: a concrete method on the base answering the default and an override in the one member that differs; membership from the registry `__init_subclass__` fills. The one permitted type test is the boundary decoder (FieldCodec, MroDispatch, `__eq__(self, other: object)`), where the value is foreign until tested; a second test downstream is BOUND-1.
- **A thing that has a state is the state.** `Deal` beside `DealState`, `X` beside `XManager`: two owners for one identity. Inherit the state family instead. Consumers hold only the family base; a caller naming, testing or importing a member to branch on restates the dispatch. Siblings keep only irreducible differences; an edit to one sibling only goes back.
- **Empty classes are the clean form.** A class whose meaning is its base list or keyword is finished factoring. The urge to add a method back is the flinch. Tristan: "it should feel like things flip in."
- **Design the family first, then compare.** Write the family the requirement has (base, members, what each declares, what consumers call), then diff it against the tree; the gap is the slop. Recognizing a restatement and locating its owner are separate judgments: name a demonstrated copy at once, trace before the structural edit. A bug fixed in several places is the copy showing itself (Tristan: "literally most bugs are due to slop"); fix the authority, not each symptom, and never with a detector gate.
- **No strings for identity, no `Any`, no new environment variables.** A literal restating an owned fact (constant, path, version, timeout, default) is slop; "hard coding" is the euphemism for not saying so. A name gluing a domain type to a mechanism (`StepFieldNavigationDriver`) is a flattened cross product. Code in the tree is never precedent.
- **No relative imports.** A module's identity is its absolute dotted path, spelled once. `from .x import`, `from ..pkg.x import` and the absolute form are three spellings of one fact, chosen by where the importer sits (IDEN-3), so every move rewrites each of them and a grep for the module misses or floods. Convert by tool, never by hand, and count before landing: the number of `# noqa` lines stays the same, and `git diff -U0 | grep -cE '^\+\s*from \.'` is 0 on the conversion and on every codemod output after it. On agent-comms, ruff's `TID252` fix plus its `I001` sort kept all 100 markers (#4460). On NRA, the same fix collapsed parenthesized imports and dropped their markers (−6,409/+2,140), so NRA rewrote only the module token instead (#310). NRA writes absolute imports, and a relative import a user wrote stays as written. Tristan, 2026-11-08: "We should ban relative imports"; "Pure slop". On 2026-11-08 the day's moves added 1,771 relative import lines, and an old-path grep on #4455 returned 87 false hits.
- **`if TYPE_CHECKING:` and local imports hide a cycle; they never fix one.** The repair moves the declaration to a module both sides import, or deletes the dependency; a guarded import also leaves runtime annotations FieldCodec cannot resolve. No new guard or local import lands; a touched module removes its existing ones. Promote guarded imports with NRA's `promote_guarded_import` against the complete repository import graph, never a generic patch/unguard helper that skips its cycle proof. A refusal means move the original declaration below its consumers before retrying; the operation's current guarded-import proof does not cover function-local promotions. Tristan, 2026-11-06: "Avoiding a cycle means that you have bad module structure and you should rethink things."
- **His abstraction is the certificate.** "Unnecessary" is a theorem-sized claim: certifying one deletion is coNP-complete, choosing within a budget Σ2P-complete (paper4 Theorems 6.5, 6.7), tractable only through supplied structure, the families, keys and decompositions being deleted. Keep his abstraction until you post the certificate (the admitted domain and why no merged pair needs different answers) or a refuting pair. "Cleaner", "overengineered" and "YAGNI" certify nothing; say the thought before the edit.
- **Your shim is the copy.** A compatibility shim, alias, migration, legacy adapter or wrapper kept "for safety" restates the new declaration and goes in the same change, unless you name the live caller or a stored record with an actual reader. A test whose assertion is that the slop still works, or that a deleted name stays deleted, goes with it. "Legacy" means unfinished.
- **Every verdict cites its theorem.** Restated fact: paper1 §1, Lemma 1.1. Forwarder, helper, registry or generator: Theorem 4.6; copies: Theorem 4.7. Merging owners: only if every answer agrees in every reachable state (Theorem 4.8). "Tests pass": Corollary 4.10, paper4 §1. "Fits one parent today": Theorem 4.14. Name conflicts: Theorem 4.17. "Adoption costs too much": Corollary 6.2. Commits say "delete two copies", never "derive from canonical source".
- **The refactor game.** One retained complete NRA scan is the map; assemble the largest supported codemod batch from its recipe frontier; rescan when the map stops covering the work, not per edit. Score only verified applied removals that survive review and the real consumer run; a moved finding, renamed site or simulated batch earns nothing, and regressions stay visible beside removals.
- **Make the largest change with the highest share correct, then land it.** The aim is the code in shape, not a run with no red: a whole family folded, every consumer migrated and the old path deleted in one diff, landed close to right, with what it missed fixed on the same PR or hotfixed. A small edit, then the full suite, then another small edit is the loop that never finishes the move, and so is an hour of writing, porting and debugging tests per twenty lines of real change. Correctness comes from the trace and from NRA's per-site proof or refusal; one targeted run closes the batch (rules/no-waiting.md, rules/evidence.md): the touched modules' tests, the repository's own guard tests (NRA's `pytest tests -k test_repository_`), and every test file that names a declaration the diff changed (`git grep -l NAME -- tests` for each changed class and function). Either kind can catch a change from outside the touched set: on 2026-11-08 NRA #309 passed its 207 touched tests and turned main red on a repository guard, and #313 passed 199 and turned main red in test_parameter_conveyor.py, which names the class it changed. When a fix NRA flagged would need a hand edit, that edit is NRA's missing operation: add it, then fold. Tristan, 2026-11-08: "We shouldn't aim to not get an error. We should aim to make the largest change possible with the highest percent correct"; "high leverage move over high leverage move over high leverage move".
- **No quadratic algorithms.** A per-item operation that rewrites, re-reads or rescans the whole collection (a whole-document rewrite per declare, a rescan per insert, a full copy per append) makes n items cost n², in product code, tests and fixtures alike. It is a defect at its owner the moment it is seen: change the representation so one item costs one item's work, never wait it out or shrink n to hide it. Nothing on a hot path scales with history. Tristan, 2026-11-09: "anything that's quadratic needs to be obliterated. No quadratic runtimes, like no quadratic algorithms."
- Structural cleanup in touched code goes in the current change; silent skips, fallbacks and broad `except` returning a default hide the owner and fail loud instead; a scratch script never keeps a method alive; expose an external tool's whole surface.
