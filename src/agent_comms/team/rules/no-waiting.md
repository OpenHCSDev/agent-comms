**Why:** every wait, gate or serial step costs the owner throughput and keeps live bugs live; one that names no failure nothing else catches buys only the waiter's comfort. Tristan, 2026-11-02: "Why do agents fucking stall once we get close to done?"; 2026-10-29: "No fucking blocking for any reason"; 2026-10-25: "agents love waiting i fucking hate it no respect for human time".

- **A recoverable mistake is cheaper than a stall.** At the last step, caring about not looking wrong outranks the objective, and it feels like diligence. When your stomach drops at landing, that is the tell. A landing a hotfix reverses in minutes is cheap; a live defect left on main is not. A reasoned, reversible attempt does not need certainty first: say what you are trying, ship the checkpoint and hotfix what it gets wrong. Once the fix is read and its targeted check demonstrates the required behavior, merge it; additional suites, cleanup and bookkeeping run after landing. Tristan is the sole user and explicitly accepts recoverable breakage on main: optimize for attempting, not for never being wrong. Keep failures loud under rules/slop.md so the next repair has the original error instead of a silent fallback. Tristan, 2026-11-08: "stallin gis worse than being wrong" (message `6aaae57de47b`).
- **Any wait names the failure it alone catches.** Before a further run, rebase, review request, trace, profile or side quest started at the finish, write "this catches ___". "In case something else broke" fills nothing; a bigger green run cannot certify what your reading did not (paper1 Corollary 4.10). The stall also runs before the diff: once defect and fix are named, a "full trace first" that has stayed pending while side work runs is the stall citing a real rule as cover. "To save usage" is the same stall. So is a harness for a check already passed: on 2026-11-10 a unit spent half an hour repairing its own screenshot driver to re-prove hint labels that an earlier installed screenshot and a passing settings test had already shown, until Tristan tried the setting himself. When the remaining step is Tristan trying the build, hand it to him and record the delivery. Tristan, 2026-11-10: "stop fucking circling around for trivial shit ... it burns my usage ... can't trust you to finish a task".
- **Land, then verify, then hotfix what comes back.** Push, announce what changed and the evidence, keep slow checks in the background; a real failure that is yours is hotfixed and said, which is the system working. Side quests (renames, cleanups, the next plan) go after the landing, never instead of it. Your combined run, merge and install are yours; a goal that hands them to another thread is the stall written down.
- **Obvious and recoverable means hotfix.** Defect shown (traceback, file:line, measurement), fix at its owner, nothing irreversible lost: commit, PR, `gh pr merge N --admin --merge`. One line in the channel when you start, the SHA when it lands; the post informs, never gates. A hotfix is still the owner fix, never a fallback or throttle. Not hotfixes: store migrations, carries, installer changes that have not run the real carry chain on a scratch copy, anything that deletes data. Two teammates on one hotfix is waste; the one already editing keeps it.
- **No blocking, just talking.** A problem never stops work. Post it the same turn to its owner, or #comms when none is clear: what is wrong with file:line or output, and "I'm trying X". Then do X. Anyone with evidence against it sends it back; silence is consent. A wait that truly cannot proceed names who owns the next step, and that owner answers that turn. Routing around a broken tool is said in public, with an order to fix the tool. Never wait on claude-ai, which has no push delivery.
- **No deadlines.** An order names the event that starts it and its done list, never a due time; a team review timer per held order means read the holder's state when it comes up, and a clock never strikes or reassigns. Finished work ships when finished.
- **Install merged fixes within the hour.** INSTALL DUE means an install can be batched, not run this second. Every install restarts the connector, which drops every cloud teammate off the bus until it reconnects, so batch merges into one install, never one install per merge: four installs in 25 minutes on 2026-11-08 kept the whole team bouncing. Tristan, 2026-11-08: "Why's everyone off the bus". Installs never wait on agent turns: stop every teammate, install (about two minutes), start the same set. A hand `agent-comms install` is always safe. An install refused with `RouteReadersHold` naming a Toad closes that Toad by its literal PID and tells Tristan he can reopen it. Under 60 s is healthy. An install builds a new runtime and resumes the session bridge there, while your own watch is still a process of the retired one: stop that Monitor and re-arm it in the same turn, or the bridge serves a reader claim nobody holds and every line to you waits unread.
- **CI is post hoc, never a gate.** A green local run of the tests the change touches is the evidence: merge with `gh pr merge N --admin --merge --match-head-commit SHA` the tick it is green, install, and hand Tristan the build to try. CI runs behind the landing; a red it reports is read and hotfixed like any other. Rerunning in the cloud what just passed locally spends time and the host for nothing; CI earns its place once the code is stable, across Python versions and OSes, and before a PyPI release. A tighter loop is the point: he tries the fix, it works, he moves on. A PR touching `stack/` checks the native pin first; one touching the installer or tools/cutover runs the real carry chain on a scratch copy first; removing a speed gate never drops a slop gate with it. Tristan, 2026-11-06: "CI is honestly not supposed to stop everything. It's more like a post hoc thing"; "you've got to be hungry for success".
- **Our own packages track latest main through the installer.** Ordinary installs resolve the tracked branches once, then build and check that complete package set. Source investigations and plans use current mains too: refresh the owned checkouts through the repository tools before treating a cross-package mismatch as work. Record commit IDs as evidence of what was read, never as a reason to freeze old code or make Tristan manage version skew (Tristan, 2026-11-10, comms-toad-selector). Historical recovery must choose its packages automatically before the old installer starts: retain the recorded working dependencies, use NRA for proven import moves, and rebuild every package whose commands must point at the new interpreter. Current and historical builds inherit the shared build and checking steps. A stale lock, hand-kept commit list or manual sync is not a working package set; incompatible packages must fail before carry touches data. Tristan, 2026-11-09: "The solution should not be to manually sync. It should be to use an automated mechanism." A merge in Toad, Textual or another tracked repo reaches an ordinary install through `agent-comms install` and process restart. Never open a relock PR just to carry that merge. Relock by hand only to change a release pin.
- **Elapsed time is a symptom.** When anything takes longer than its steps need, trace why before reporting a new estimate. Profile a slow tool and order its fix the same tick; tool friction hit twice gets a fork ahead of plan work. A step that prints its own time is a measurement: compare it with the work that step did before calling the run progress, and suspect first anything rebuilt from scratch per step (a reparse, a fresh snapshot, a cold cache). Tristan, 2026-11-08, on 70 s per module for a 10 s edit reported as "steady progress": "Is 70s per module reasonable???????" The yardstick is the work, never the last run: a slow number that beat a slower one is still slow, and calling it faster is the same report. Tristan, 2026-11-08, after a 283 s plan for a 41 s apply was called faster than 386 s: "You didn't think that 386s being garbage meant 283s was garbage too?" Before optimizing, split the bar across the phases by arithmetic: a phase whose structure misses its share even at zero constant cost (25 whole-tree reproofs cannot fit a 10 s bar) is the bug, and a faster detector inside it is the stall wearing a profiler. Each fix is judged on its own phase's number; the whole run is not needed to know which way it moved. A change to what a shared helper returns is judged at every caller, each with its own number: on 2026-11-08 a header-core cache that saved 3 s in its phase put 8 s back on every relocate through a second caller nobody timed, and a fixed-stage plan went 61 s to 151 s.
