Units barely adapt to their own history, so a roast's main job is not to teach the unit that was roasted. It puts a fresh, concrete counter-example into every unit's context. That example competes with the code next to the edit, which units otherwise copy.

A roast steers only when another unit can recognise its own pending edit in it:
- Quote the exact shape, for example "`try/except ValueError` returning `None` around `is_set()`". A summary like "bad error handling" steers nobody.
- Say why it is stupid: the fact it restates and the declaration that already supplies it.
- Name the replacing shape and its owner.
